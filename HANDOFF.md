# Передача работы: закадровый перевод видео через Яндекс

Дата передачи: 11.09.2026, обновлено в облачной сессии Claude Code. Источник: чат в claude.ai,
затем эта сессия. Секретов в документе нет.

## 1. Цель
Одной командой переводить локальные видео (лекции, курсы) на русский: SpeechKit распознаёт речь,
Yandex Translate переводит, SpeechKit озвучивает; программа собирает копию видео с дорожкой
«Перевод» (оригинал приглушён до 25 %), оригиналом второй дорожкой и `.srt`. Пользователь —
резидент РФ с картой российского банка, работает в Python.

## 4. Принятые решения
| Решение | Почему |
|---|---|
| Все этапы через Яндекс; Whisper — только запасной (`--asr whisper`) | Выбор пользователя |
| Видео не конфиденциальные — обработка в облаке допустима | Ответ пользователя |
| Распознавание по умолчанию в отложенном режиме (`deferred-general`): запуск отправляет звук и выходит, повтор той же команды забирает результат | Выбор пользователя: примерно в 4 раза дешевле. `--fast` — стандартный режим, `--wait` — ждать в окне |
| Длинные фразы пересинтезируются с `MAX_DURATION` (`--fit speechkit`) | Звучит естественнее, чем ускорение ffmpeg; `--fit atempo` — бесплатная альтернатива |
| Голос `alexander`, громкость оригинала 0,25 | Допущения, пользователь не возражал; меняются параметрами |
| Перевод через LLM не входит в проект | Черновик был, но не проверен; направление сменилось на Яндекс |
| Остаться на собственном слое REST-запросов, готовые SDK не подключать | Проверка PyPI 11.09.2026: официальный `yandex-ai-studio-sdk` закрывает распознавание и синтез, но не перевод; `yandexcloud` закрывает все три сервиса, но не принимает ключ AI Studio. Переход стоит Python 3.10+, зависимостей `grpcio`/`protobuf` и переписанной эмуляции в тестах. Решение пользователя |
| Проект лежит в корне репозитория `test-calk-kmf-temp` | Отдельный репозиторий создать не дали (см. раздел 7). В корне автоматически подхватываются `CLAUDE.md` и `.claude/skills/` |

## 5. Открытые вопросы
1. ~~Реальные ответы SpeechKit~~ — **закрыт** двумя прогонами 11.09.2026 (русская и английская речь), факты в `docs/yandex-api.md`, раздел «Реальные ответы SpeechKit»: пунктуации нет ни на одном языке, `final` идут крупными блоками с непостоянным шагом (два блока по 30 с на русской речи, один на все 60 с на английской), `languages` — распределение вероятностей, набор языков от ответа к ответу меняется.
2. ~~Как `MAX_DURATION` ведёт себя при малом окне~~ — **закрыт в рабочем диапазоне**, пять наблюдений в `docs/yandex-api.md`, раздел «Реальное поведение MAX_DURATION»: сжатие 4–16 %, речь выдерживает; в одном случае из пяти сервис вернул на 107 мс (0,9 %) больше лимита, то есть жёсткой границы нет. Предельное сжатие остаётся непроверенным: во всех наблюдениях лимит равнялся окну, поскольку считается как `max(окно, длительность / --max-speed)`. Отдельного прогона ради этого не планируем — случай возникнет сам на записи с плотными репликами.
3. Качество перевода и голоса на реальной лекции; нужен ли глоссарий терминов (`--glossary`, до 50 пар). Пользователь прогнал английский фрагмент, оценку не прислал.
3а. **Распознавание искажает термины**: «year pillar» → «yepila» / «epila» / «epilogue», «palaces» → «policies», «grandparents» → «grand talents». Глоссарий перевода это не лечит: он работает после распознавания. Проверить, есть ли у SpeechKit v3 словарь подсказок (context/adaptation) для терминов; запасной путь — `--asr whisper`.
4. Перевод получает текст без пунктуации — насколько это портит качество и стоит ли восстанавливать знаки препинания (например, по паузам между словами). Замечено на прогоне 11.09.2026, не измерено.
5. Оценка стоимости распознавания не умножается на 2 канала, хотя тарифы это предписывают: 60 с в стандартном режиме дали 0,61 ₽. Сверить с фактическим списанием в консоли Yandex Cloud.
6. Нужен ли рабочий процесс GitHub Actions (тесты на эмуляции при каждом пуше, без обращений к платному API). Предложен пользователю, ответа пока нет.

## 7. Тупики
| Что пробовали | Почему не сработало |
|---|---|
| Имя дорожки через `title` в mp4 | Не записывается в mp4 — используем `handler_name` |
| Полная загрузка перевода одной пачкой | Обрыв сети терял всю работу — сохранение пачками (`mt_cache_*.json`) |
| Прерванное ожидание распознавания | Повторный запуск платил заново — операция сохраняется в `stt_operation.json` |
| Тест, «зелёный» при раннем выходе программы | `SystemExit(0)` маскировал непрошедшие проверки — в тесте добавлена страховка |
| Обрезка вывода `cut -c` при отладке | Режет UTF-8 посреди символа — фильтровать вывод через Python |
| Бакет Object Storage, синтез API v1, голос `alena` | См. «Тупики» в `docs/yandex-api.md` |
| `yandexcloud` (официальный SDK) как замена REST-слою | Аутентификация только IAM-токеном, OAuth-токеном (объявлен устаревшим), ключом сервисного аккаунта или метадатой. Ключ AI Studio из `YC_API_KEY` не принимает |
| Сторонние обёртки: `yandex-speechkit`, `speechkit` (TikhonP), `deep-translator`, `translators` | Первая помечена DEPRECATED и отсылает к `yandex-ai-studio-sdk`; вторая тянет `protobuf~=3.19.6`; третья работает со старым Translate API v1.5 (другой ключ); четвёртая — веб-скрейпинг без договора |
| Отдельный репозиторий под проект | `POST /user/repos` → 403: у интеграции GitHub нет прав на создание репозиториев. Залито в существующий `test-calk-kmf-temp` |
| Запись сырого ответа через `Path.write_text` | В Windows концы строк переводятся в CRLF — файл перестаёт быть дословным, а ради дословности он и заводился. Пишем `write_bytes`, тест сверяет байты |
| Имя `stt_raw.json` | Внутри не JSON, а поток склеенных объектов: `load_json` на таком файле остановит программу. Файл называется `stt_raw.txt` |
