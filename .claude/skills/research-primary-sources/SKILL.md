# Исследование по первоисточникам

> Адаптация навыка `research` из mattpocock/skills (MIT). Оригинал: https://github.com/mattpocock/skills/blob/main/skills/engineering/research/SKILL.md

## Алгоритм

1. **Запусти фоновый субагент** на исследование, чтобы продолжать работу, пока он читает.
2. Субагент проверяет вопрос **по первоисточникам** — официальная документация, исходный код, спецификации, первичные API — а не по вторичным пересказам о них. Каждое утверждение прослеживается до источника, который им владеет.
3. Субагент пишет выводы в **один markdown-файл**, указывая источник каждого утверждения.
4. Файл сохраняется туда, где проект уже хранит такие заметки. Если конвенции нет — в разумное место, с явным указанием, куда именно.

## Иерархия доверия к источникам

| Уровень | Тип источника | Пример |
|---|---|---|
| 1 — высший | Исходный код, спецификация, стандарт | Репозиторий проекта, RFC, ISO |
| 2 | Официальная документация вендора | docs.* сайта продукта |
| 3 | Первичный API, ответ сервиса | Реальный ответ endpoint'а |
| 4 | Официальный блог/changelog вендора | Release notes |
| 5 — низший, только как указатель | Вторичные материалы: статьи, форумы, ответы LLM | Stack Overflow, блоги |

Источник уровня 5 допустим только как указатель на источник уровней 1–4. Утверждение, опирающееся только на уровень 5, помечается как непроверенное.

## Требования к выходному файлу

- Каждое фактическое утверждение — со ссылкой на конкретный источник (URL, путь к файлу, номер раздела спецификации).
- Утверждения, которые не удалось подтвердить первоисточником, вынести в отдельный раздел «Не подтверждено».
- Противоречия между источниками фиксировать явно, а не выбирать удобный вариант молча.
- Указать дату исследования: факты о текущем состоянии мира устаревают.

## Запрет

Не выдумывать источники, ссылки, номера версий и цитаты. Отсутствие источника — это результат исследования, а не пробел, который надо заполнить.
